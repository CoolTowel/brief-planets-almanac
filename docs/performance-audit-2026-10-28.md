# 生成耗时与精度取舍调查

本次仅新增诊断脚本、实验输出与此报告；未修改 `almanac/`、天文引擎、正式采样方式或既有数据。所有近似算法与排版优化仅在 `output/performance-audit/` 中隔离试验，尚未接入正式入口。

## 实测条件

2026 年、UTC+08:00、北纬 40°、海拔 0 米；默认 15×15 英寸、300 dpi，输出 PNG 和 PDF。Python 3.12.13 / NumPy 2.4.4 / Astropy 7.2.0 / Matplotlib 3.11.2 / SciPy 1.17.1 / Pillow 13.0.0，固定引擎校验值记录在生成数据集 manifest。

运行项目已有 `output/runtime2027/Scripts/python.exe`，单进程顺序测量，没有同时运行其他诊断计算。计时为本机单次墙钟时间，适合判断数量级，不能视为稳定基准分数；函数细分计时存在嵌套，不可重复相加。

| 阶段 | 实测耗时 | 说明 |
| --- | ---: | --- |
| 全年出没、中天、晨昏事件表 | 7.916 秒 | 包含日月、五行星、五恒星 |
| 均时差 | 0.018 秒 | 无需优先优化 |
| 逐分钟太阳高度 | 16.945 秒 | 525600 次 Equator + Horizon |
| 数据生成合计 | 24.954 秒 | 校验、写入等剩余约 0.093 秒 |
| 月相符号构建 | 3.527 秒 | 包含计算和 Matplotlib 图元构建 |

| 其余绘图和导出 | 4.641 秒 | 包含背景着色约 0.297 秒 |

| 生成数据和绘图总计 | **54.710 秒** | 不含命令启动与顶层导入 |

关闭恒星后，绘图 18.756 秒，其中文字排版 10.938 秒。GUI 开关目前仅影响显示，全年数据仍计算恒星；五颗恒星的出没及中天搜索合计约 2.143 秒，不是最大瓶颈。

## 第一优先级：文字避让中的多余工作

位置：`almanac/labels.py` 的 `CurveLabels.draw()`。

每段曲线最多遍历 49 个候选位置，每个候选都逐字创建 Text、获取包围盒，再用 Python 循环与所有月相和已放置文字做矩形碰撞判断。PNG / PDF 各做一遍。即使已经找到当前规则下最优、没有月相碰撞的位置，仍遍历后续候选。

独立原型保留原有评分、顺序、字体、旋转与字距，仅优化搜索和矩形比较：

| 排版方案 | 开启恒星绘图耗时 | PNG 对比 |
| --- | ---: | --- |
| 当前实现 | 29.756 秒 | 基线 |
| 取得最优无碰撞位置后提前结束候选搜索 | 14.182 秒 | 全部像素一致 |
| 上述优化 + NumPy 批量矩形碰撞比较 | **10.861 秒** | 全部像素一致 |

两份 PDF 用 Poppler 栅格化到 1500×1500 后，像素也全部一致。验证限于本次 2026 配置；正式接入时应扩展到不同年份、DPI 和恒星开关的布局回归。

此方案不改变天文结果，也无需降低图像精度。仅这一项即可把总耗时估计从 54.7 秒降到约 35.8 秒。上次新增的标注实现确实引入了明显开销，应优先处理。

## 第二优先级：背景太阳高度的采样密度

位置：`almanac/calculations.py:102`，`compute_sun_alts()`。

全年每分钟都从头执行完整太阳赤道坐标与地平坐标转换，包括 VSOP、光行时、观测者位置、岁差章动等。一天 1440 点的 cProfile 显示约 47.4 万次函数调用；累计时间主要在 Equator，而不是生成 Time 或写入文件。该数组的正式调用方目前只用它生成背景颜色，事件曲线由另外的搜索函数独立计算。

已有太阳背景调用明确使用 `aberration=False`、`Refraction.Airless`，不是误开了这两项校正。不能直接取消 `ofdate=True`：Horizon 要求当天赤道坐标，改成 J2000 会造成坐标基准不匹配。

Astronomy Engine 本身使用截断模型，官方设计目标约为 ±1 角分，并非高精度航天星历。这里更值得减少的是完整模型的重复调用次数，而不是继续删模型项。[官方说明](https://github.com/cosinekitty/astronomy)，[Horizon 坐标要求](https://github.com/cosinekitty/astronomy/blob/master/source/python/README.md#horizon)。

### 直接插值高度角的对照试验

以北纬 40°、海拔 0 米的 2026 / 2028 全年原始逐分钟结果为基线。连续跨午夜插值，最后一个采样点显式保留，未外推年尾。以下取两年的最大值；角秒是角度单位，不是时间秒。

| 方案 | 晨昏区间最大新增高度误差 | 高度阈值的最大时间偏移 |
| --- | ---: | ---: |
| 每 5 分钟，线性 | 6.261 角秒 | 0.951 秒 |
| 每 10 分钟，线性 | 26.021 角秒 | 3.938 秒 |
| 每 10 分钟，三次样条 | 0.001565 角秒 | 0.000158 秒 |
| 每 30 分钟，三次样条 | 0.1280 角秒 | 0.01298 秒 |
| 每 60 分钟，三次样条 | 2.130 角秒 | 0.22474 秒 |

晨昏区间为太阳高度 -18° 到 0°。时间偏移由两份逐分钟序列在 -18°、-12°、-6°、0° 的交点局部线性定位得到，仅描述背景高度阈值，不代表独立 SearchRiseSet / SearchAltitude 事件计算误差。事件表在此方案中不变。

**不能直接把上述三次样条结论推广到整个天空。** 补测赤道、回归线和高纬度后发现，高度角在接近 ±90° 时变化不够平滑。2028-06-21、纬度 23.44° 的单日样本中，每 10 分钟直接对高度角做三次样条，全天最大误差达到 **0.573°**，尽管晨昏背景仍很准确。单纯在绝对高度 >85° 的点恢复精确计算也不足以消除相邻插值振荡，因此不推荐直接采用这一简单方案。

### 推荐候选：插值 sin(高度)，并保留极值附近精确计算

建议每 10 分钟调用原引擎得到高度，将高度正弦值做三次样条，再反正弦恢复每分钟高度；若恢复的绝对高度 >85°，该点重新调用原引擎。这样可以避开直接对高度角插值的天顶、天底尖点，并保持数组仍是完整的每分钟高度角。

实测结果：

- 北纬 40°、2026 / 2028 全年：全天最大新增误差 **0.01659 角秒**，晨昏最大 **0.001155 角秒**。
- 两年背景着色前的 RGB 通道最大差，折算 8 位颜色标度为 **0.0000098 个色阶**。高度阈值局部交点最大偏移 **0.000175 时间秒**。
- 边界样本：2028 年 1 月 1 日、2 月 29 日、3 月 20 日、6 月 21 日、9 月 22 日、12 月 21 日、12 月 31 日；纬度 0°、23.44°、40°、60°、66.5°、80°、-40°；UTC+05:45，海拔 0 米，共 **49 个完整日**。启用 >85° 精确回算后，全天最大新增误差 **0.1491 角秒**。
- 高纬度太阳高度样本用于精度诊断，不意味着现有图框已支持极昼极夜。
- 2026 北纬 40° 的 10 分钟稀疏原引擎求值 + 直接样条重建实测 **1.780 秒**，52561 个精确采样点，采样点值与基线完全相同。正弦变换及还原只增加少量数组运算；此纬度全年不触发 >85° 回算。因此推荐方案预计约 **1.8 秒**，属于基于实测的估计，尚非接入正式流程后的整链路计时。
- 热带可能需要额外回算，本次单日样本中回算比例最高约 5.6%；运行时间将高于北纬 40°，不能一律宣称十倍加速。

对于当前年历背景绘图，以上新增误差足够小，且出没、中天等事件时刻可完全保持原样。这些是相对当前模型的实测误差，不是相对真实天体位置的绝对误差，也不是对年份 2..9998、所有纬度和海拔的数学保证。正式接入仍需固定输入做更广泛回归，记录采样算法及版本，不能把新近似数据伪装成旧算法的完整逐分钟求值数据。

原始颜色函数在太阳高度 0° 处存在颜色跳变，直接插值试验的全画布颜色差有时达到 255；这些点在当前 40° 的日出日落边框外。另测可见夜间区域，5 分钟线性最大差为 0.045 个色阶、10 分钟线性为 0.191 个色阶。报告未用隐藏的昼间跳变夸大可见背景误差，也未修改原颜色函数。

## 其他精度与性能取舍

- 出没/高度搜索容差和中天收敛阈值均约 0.1 秒，确实比图中读数所需更细；当前画布 0.1 时间秒约对应横向 0.0043 像素。但这些搜索合计约 8 秒，放宽容差只能省去部分迭代，无法解决 22 秒排版和 17 秒背景的主要开销。建议先保留。
- 恒星搜索约 2.14 秒；为关闭恒星跳过这些计算会涉及数据集完整性协议，不应作为首个优化。
- 背景颜色转换约 0.3 秒，虽有 `np.vectorize`，不是主要瓶颈。
- 月相图元构建约 3.5 秒；500 点轮廓可以另行研究，但不应为小收益顺带改变月面几何。
- GUI 当前每次点击都创建新数据集。仅切换恒星或调整标注时，显式选择并校验已有数据集重新绘图，可以完全省去约 25 秒计算；应作为明确的“重绘已有数据”功能，不是默默复用来源不明的数据。

## 推荐实施顺序

1. 接入不改变排版结果的候选提前结束和矩形碰撞批处理。预期总耗时约 36 秒。
2. 用户确认后，接入每 10 分钟采样、sin(高度) 三次样条及 >85° 精确回算，保留事件算法。两项合用在当前 40° 配置估计总耗时 **约 21 秒**，相对约 55 秒为 **约 2.6 倍加速**。此为分阶段测量推算，尚未作为正式整链路计时结果。
3. 如经常调图，再增加显式加载已有数据集的 GUI 重绘入口。

第 2 项属于 AGENTS.md 保护范围，需要用户确认具体方案后实施。当前没有修改正式天文逻辑。
