# 新月、满月出没图标选择验收

## 授权范围与规则

用户明确授权：新月、满月各自匹配与精确月相时刻最近的一次月出和一次月落，上下弦保留旧逻辑。用户进一步明确：满月省略选中月出前两个当地日期的普通月出、选中月落后两个当地日期的普通月落；新月省略选中月落前两个当地日期的普通月落、选中月出后两个当地日期的普通月出。按自然日期筛选，不以 48 小时或补足两次事件代替。

实现位于 `almanac/render.py`。先从全部有效缓存事件中匹配最近时刻，允许两个专属图标分属不同夜晚；只替换选中的同类事件，不再删除整条朔望夜晚行。等距时选较早事件。保留特殊符号原来的日落前／日出后 2 小时显示范围；不因最近事件不可见而改选较远事件。上下弦仍按月相时刻所属夜晚放置并省略该行普通符号。曲线文字避让使用实际画出的月亮坐标，不再把已省略或未显示的事件当障碍。

年界附近，当年外事件可能更近时，用固定引擎和相同观测者、折射与月面上缘定义检查相邻年事件。年外事件若更近，不在图内绘制，也不改选年内较远事件。没有有效年内候选时不绘制替代事件。月相搜索区间仍保留原本的当地本年 1 月 1 日正午至次年 1 月 1 日正午。

未修改月相搜索函数、月出月落事件值、太阳背景、均时差、晨昏计算、时间坐标约定或月面几何；未改写已有数据。此次变更仅在获准范围内选择显示的事件和普通符号。

## 固定输入与环境

全部采用 UTC+8、北纬 40°、东经 120°、海拔 0 米。数据为以下已存在且通过 manifest 完整性校验的运行目录：

Python 3.12.13，NumPy 2.4.4，Matplotlib 3.11.2，Astropy 7.2.0，SciPy 1.17.1。数据算法版本 1.1.0；固定天文引擎 SHA-256 为 `41248c7b1edbf9d11119528eef7455a6dc55abde9f1aab40d363015e956c1729`。

修改前后的全部图标记录保存在 `output/lunar-selection-validation/before.json` 和 `after.json`。独立审计按缓存事件的 UTC 时刻二分定位相邻候选，核对每个朔望图标；按当地日期单独推导省略集合，核对每个普通图标。三年全部通过，上下弦图标的时刻、相位、行号、横坐标逐项相同；原位置仍绘制的普通图标保留相同时间和相位值。

这些差异属于图标事件选择的预期变化，不是出没时刻的重新计算或精度变化。真实三年核对验证匹配规则；科学星历绝对精度不由此回归审计单独证明。

正式测试命令 `python -m unittest discover -s tests -p "test_*.py"`：**68 项通过**。新增覆盖最近事件跨夜、闰日、缺失事件、等距选早、先匹配后判断显示范围、年界外更近事件不替代、前后两天同类筛选，以及超过 48 小时但属于前第二自然日的情况。原观测者测试的预期次数按明确要求减少四个普通符号，仍检查全部调用的观测者配置。

2026、2028 的完整 PNG/PDF 位于 `output/lunar-selection-validation/<运行目录名>/`，通过正式入口 `main.py render --run-dir ... --output-root output/lunar-selection-validation --no-stars` 生成。两份 PDF 使用 Poppler 实际栅格化检查，并检查十月至十一月局部。重新审计日期排布：104／106 个日期数字均无满月重叠，月份横线与日期相交数均为 0。

复现脚本、环境和结果另存于同目录 `snapshot.py`、`audit.py`、`audit.json`、`layout-audit.py`、`layout-audit.json`；该目录按现有规则忽略，不提交临时图像或缓存。新规则应用于旧数据集只需重新绘图，无需重新生成全年星历。
