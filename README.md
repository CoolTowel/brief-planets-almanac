# 行星年历

程序使用命令行明确指定的年份、固定 UTC 时区和纬度生成全年星历，输出完整 PNG / PDF。所有正式计算与绘图共用一个不可变的 `TopoContext`；默认海拔 **0 米**，观测经度由时区自动推导。

## 安装

使用 Conda 的 `almanac` 环境（Python 3.12）并安装锁定依赖；已有该环境时跳过创建命令：

```powershell
conda create -n almanac python=3.12 pip
conda activate almanac
python -m pip install -r requirements.txt
```

Astronomy Engine 使用项目自带的固定源码，来源、SHA-256 和 MIT 许可证见 `almanac/_vendor/`。无需另行安装 `astronomy-engine`，也不在运行时下载天文代码。

## 运行

以下命令在项目根目录执行，先运行 `conda activate almanac`。也可通过 `conda run -n almanac python main.py ...` 运行，无需激活环境。项目不再使用 `output/runtime2027` 本地虚拟环境。

轻量图形界面：`python main.py gui`。只需填写年份、固定 UTC 时区、纬度，选择是否显示恒星，然后点击“生成 PNG / PDF”。界面显示计算进度，完成后可打开结果目录。海拔保持默认 0 米；运行期间界面保持响应。使用 Python 自带 Tkinter，无新增第三方依赖。Windows 下也可双击 `gui.pyw`，前提是 `.pyw` 已关联到安装了本项目依赖的 Python。

```powershell
# 生成 2027 年、UTC+8、北纬 40 度、海拔 0 米的数据和完整图像
python main.py all --year 2027 --utc-offset=+08:00 --latitude 40

# 只生成数据；这里显式使用海拔 40 米
python main.py generate --year 2028 --utc-offset=+08:00 --latitude 40 --elevation 40

# 西时区、南纬；时区参数使用等号避免负号歧义
python main.py generate --year 2027 --utc-offset=-05:00 --latitude=-30

# 用生成命令打印的目录重新绘制，不重新计算全年星历
python main.py render --run-dir "data/runs/<运行目录名>"

# 显式允许替换该数据集已生成的图片
python main.py render --run-dir "data/runs/<运行目录名>" --overwrite

# 关闭恒星曲线及其标注（all 和 render 均支持）
python main.py render --run-dir "data/runs/<运行目录名>" --no-stars
```

`all` 和 `generate` 必须提供 `--year`、`--utc-offset`、`--latitude`；`--elevation` 默认 0 米。时区接受 `+8`、`+08:00`、`+05:30`、`+05:45` 等固定偏移，范围 UTC-12:00 至 UTC+14:00，不使用夏令时或城市时区。`render` 不接受另一份年份、纬度、海拔或时区参数。

可使用 `--data-root` 指定新数据集的父目录，`all` / `render` 可使用 `--output-root` 指定图像父目录。默认分别为项目下的 `data/runs/` 和 `output/`，不会因命令的工作目录不同而改变。首次生成完整年历需要计算全年事件与太阳背景，请等待命令输出进度。

## 时间和观测地约定

- `TopoContext(year, utc_offset_minutes, latitude_deg, elevation_m=0)` 只接收这些原始参数，不接受单独指定经度。
- 经度等于时区偏移小时数乘 15；UTC+8 对应东经 120 度，UTC+14 对应规范化后的西经 150 度。规范化经度不会改变原始时区或日期归属。
- 计算对象代表该时区标准经线上的观测点，不代表某座城市的真实经度。
- 每行从当地当日正午到次日正午，左闭右开。横坐标 -6 表示当日 18 点，0 表示次日午夜，+6 表示次日 6 点。最后一行包含下一年 1 月 1 日的凌晨，第一行不包含本年 1 月 1 日上午。
- 天数、闰日、月份边界和左右日期标签来自真实日期序列。UTC 转换集中在 Topo 对象，不依赖宿主日期或系统时区。
- 数组使用零基索引，FITS `Day` 与图中的夜晚行号使用一基索引；缺失天文事件保留 `-999` 标记，绘图断开该段。
- 均时差沿用现有 `12 - HourAngle(Sun)` 符号及午夜采样。它与通常“视太阳时减平太阳时”的均时差定义反号，本轮不改变其图示含义。
- 本轮保留现有日出日落边界版式。遇到无日出或日落等不能成立的图框，仍可生成星历数据，但完整图像生成会明确报错，不伪造事件。

## 每次生成的数据集

相同配置重复生成也会新建目录，例如：

```text
data/runs/2027_UTCp0800_N40_E120_H0m_<UTC创建时间>_<唯一后缀>/
    manifest.json
    rise.fits
    set.fits
    transit.fits
    twilight.fits
    EOT.npy
    sun_alts.npy
```

Manifest 记录完整输入、派生经度、UTC 起止、日期范围、天数、恒星映射、数据单位和形状、文件校验值及计算版本。写入完成并校验成功后才发布完整状态。加载缺失、损坏、未完成或配置不一致的数据会报错，不会偷偷回退到旧年份目录。

从算法 1.1.0 起，太阳背景按用户确认的 **每 3 分钟**精确采样，对高度正弦值做三次样条，再恢复原有每分钟网格；绝对高度大于 85° 的点精确回算，年末最后一分钟也精确采样。输出仍为 `(全年天数, 1440)` 的无折射高度角（度）。采样间隔、插值方法、极值回算条件写入 manifest 的 `algorithm.solar_altitude`；`derived.sample_interval_minutes=1` 表示输出网格间隔。已知 1.0.0 逐分钟数据在完整校验后仍可读取，保留原版本记录，不会自动重算或改写。出没、中天、晨昏事件时刻及均时差算法不变。

完整图像写入 `output/<同一运行目录名>/almanac.png` 和 `almanac.pdf`；默认开启图框、天体曲线、月相、背景、网格、均时差、中天赤经和日期文字。PNG 为 300 dpi，默认画布 15×15 英寸。重复绘制须显式使用 `--overwrite`。

除月份外，所有文字（日期、小时、中央赤经数字、行星和恒星、均时差与晨昏标注）统一使用 `fonts/SourceHanSansSC-Regular.otf`（思源黑体 Regular）9 pt。两侧月份使用 `fonts/SourceHanSansSC-Medium.otf`（思源黑体 Medium）10 pt，从上到下竖排，额外字间距为 1.5 pt。月份固定在各自日期区间的中央，不为月相图标移动位置。

行星出、没、上中天及恒星标注逐字沿现有曲线排布。文字实际笔画到线条边缘的法向间距统一为 2 pt，横排、竖排和左右侧使用同一规则；避碰只调整沿线位置，不额外增大间距。PNG 和 PDF 在绘制时分别按实际字体度量和曲线切线排字，避免导出 DPI 改变文字间距。曲线标注避开边框、中央刻度和其他标注，并优先选择避开月相和其他曲线交叉的位置。每个连续可见段通常只标一次；弧长至少达到 650 pt 且不小于文字长度的 12 倍时，才尝试在前后两段各标一次，两处中心沿线至少相距 240 pt 且不小于文字长度的 6 倍。过短或过密、没有容纳空间的可见段会略去标注。不同年份的曲线文字位置会自动调整，不复制 2026 参考图的固定坐标。标题与介绍文字不生成。

事件线型按 2026 参考 PDF：出为点划线（6、1.75、1、1.75 pt），没为虚线（8、4 pt），上中天为实线。恒星也沿用对应事件线型；颜色与线宽保持现有设置。

金星的出没标注始终从上往下竖排；水星按标注位置切线与水平线的最小夹角决定横竖排，小于 60° 时横排，达到 60° 时竖排，反向切线同样处理。两者的“出”线放在曲线左侧，“没”线放在曲线右侧。布局检查整个文字框是否处于指定一侧，沿线避碰搜索遵循上述读向和左右侧规则。

其他标注按实际显示空间的局部切线判断读向：与水平线夹角达到 60° 时，采用汉字从上往下竖排，单字保持接近直立并随曲线略微倾斜；较平缓处从左往右沿线排列。判断针对每个候选标注位置，不以整条曲线的首尾方向或原始数据坐标斜率代替，因此跨弯曲段不会把陡斜率文字排成从下往上读。

两侧日期数字在原位置基础上统一上移 2 pt。绘图时记录现有满月符号的实际图形边界，只在字框与满月重叠时做最近距离的水平避让，并把数字限制在日期栏内；空心新月不参与避让。布局不新增天文计算，PNG/PDF 按各自字体度量处理，重复绘制不会累积位移。月份分界线和顶底横线仅在实际数字笔画距离线条边缘不足 0.35 pt 时断开，缺口在笔画左右各留 1 pt；不再用包含字体上下留白的整块文字框提前避让，日期本身的数值及月份边界对应的日期行不变。

新月、上弦、满月、下弦统一按出没时刻的实际月相角选择专属符号：以精确月相时刻为界，分别取前后紧邻的一次有效月出、一次有效月落；对每一类出没比较这两个候选的 `MoonPhase` 值与目标 0°、90°、180°、270° 的环绕角度差。目标新月的 359° 与 0° 相差 1°。精确月相时刻只用于找到前后邻居，候选优劣不按时间距离评分；角度差相等时选较早事件，恰好重合的事件只比较一次。`MoonPhase` 沿用固定引擎定义的地心日月视黄经差，不以照亮面积比例代替。

月出和月落独立选择，可分属不同夜晚行；只替换选中的同类图标，上下弦也不再按所属夜晚整行替换。先选事件，再应用原有日落前／日出后各 2 小时的特殊符号显示范围，不改选另一候选来补画。年界缺少一侧邻居时，以相同引擎、观测者和出没定义补查年外事件，最多搜索与当前数据年等长的日数；年外事件若胜出，该侧不在图内绘制，也不拿年内事件替代。月相搜索仍采用现有的本年正午至次年正午范围。

围绕选中的专属符号，只省略以下同类普通出没图标：满月月出之前两天的月出、满月月落之后两天的月落；新月月落之前两天的月落、新月月出之后两天的月出。这里的“两天”按事件的当地自然日期计算，不是固定 48 小时，也不跨过缺失事件凑足两个图标。另一类出没图标与上下弦标志不因此省略。既有星历表、准确月相时刻和月面绘制几何保持原样，已有数据集只需重新绘图即可应用新规则。

“均时差”“天文晨光始”“天文昏影终”在各自曲线的顶部、底部各标一处，同样使用思源黑体 Regular 9 pt，并随曲线倾斜。均时差文字贴在曲线远离中央刻度的一侧（2026 年顶部为右侧、底部为左侧），避开中央赤经数字。均时差优先避开月亮；沿线没有足够间隙时，可在同一侧沿法线多移 5.5 pt，不移动月亮或改变其时间位置。均时差标注随 `eot` 图层开关，晨昏标注随 `grid` 图层开关；不存在的晨昏事件不跨接或虚构曲线。文字候选搜索与矩形碰撞比较已优化。

`--no-stars` / GUI 恒星开关只控制绘图；数据集仍保留完整恒星数据，重新绘制时可以再开启。此功能不改变天文计算、数据格式、曲线采样、月面符号或夜晚日期约定。

旧的 `data/<年份>/<纬度>/` 与 `output2027` 原样保留。缺少生成元信息的旧数据不能自动转换为新数据集，避免猜测经纬度、海拔或算法版本。

## 模块与本轮修复

正式调用链为 `main → CLI → TopoContext → generate/load_dataset → render_almanac`。计算模块只返回数值和表；数据集层统一写入；绘图只使用数据集中的配置。导入模块不会读取全年数据、启动计算或创建图像。独立模块的测试参数仅写在 `if __name__ == "__main__":` 中。

保留五颗恒星：轩辕十四、大角、织女、北落师门、天狼。天狼与北落师门的负赤纬度分符号已经纠正；月面符号明确使用实际观测者；均时差不再覆盖输入年份；主图和背景来自同一个数据集。

旧入口及重复实现移至 `legacy/`，仅供历史参考，不属于正式支持的运行方式。月面几何沿用根目录版本，未替换为旧 `utils` 中不同的翻转实现。天文计算的其他修改仍遵守 `AGENTS.md`，先报告疑点，由用户决定。

## 验证

```powershell
python -m unittest discover -s tests -p "test_*.py" -v

# 对海拔40米的新数据集执行完整数值回归
python tools/verify_regression.py --run-dir "data/runs/<2027年海拔40米的新数据集>"
```

正式测试覆盖时间边界与时区、配置不可变性、无导入副作用、数据完整性与隔离、显式观测者、CLI 参数限制等；历史实验脚本不在此发现模式内。测试使用临时目录，不覆盖项目历史数据。

数值回归须先以显式海拔 40 米与旧 2027 数据对照，再验收默认海拔 0 米的新图。非授权变化的事件时刻容差为 1 毫秒，太阳高度容差为 `1e-7` 度；不通过放宽容差掩盖算法差异。
